# Meat Lovers CIMS powered by YohPal
Meat Lovers CIMS is a web-mobile restaurant control and intelligence system powered by YohPal.
## Core Objectives
1. Increase sales
2. Stop theft across all departments
3. Monitor sales, income, stock, staff, service, bar, food production, deliveries, finance, and customer
activity
4. Provide an AI-enabled website for customer acquisition
5. Support mobile-first POS usage by waiters
6. Provide management visibility through admin and monitoring dashboards
## Main Apps
- `apps/website` - AI-enabled customer acquisition website
- `apps/admin-web` - management dashboard
- `apps/pos-pwa` - waiter smartphone POS
- `apps/monitoring-web` - live monitoring dashboard
## Backend
- `backend/` - PHP API
## Database
- `database/migrations`

- `database/dumps`

# Meat Lovers CIMS powered by YohPal — Master Scope
## 1. Customer Acquisition Website
The website shall act as an AI-enabled disruptive customer acquisition engine.
It shall support:
- food menu discovery
- bar and drinks visibility
- promotions
- online enquiries
- customer lead capture
- AI assistant / chatbot placeholder
- WhatsApp and call-to-order links
- delivery lead capture
- customer feedback
- event and catering enquiry capture
- customer segmentation source
## 2. Product Segmentation
The system shall separate:
1. Food
2. Soft drinks
3. Alcoholic drinks
Each product must belong to one of these categories.

## 3. Departments Covered
The system shall cover:
1. Suppliers
2. Storekeeping
3. Food production
4. Service
5. Dispatch
6. Bar
7. Unsold cooked food
8. HRM
9. CRM
10. Deliveries
11. Product segmentation
12. Staff motivation, especially service team
13. Asset inventory
14. Finance P&L
15. Daily, weekly, monthly, and annual income statements
## 4. Anti-Theft Controls
The system shall control theft by:
- recording every stock movement
- separating store, kitchen, bar, service, and dispatch stock
- requiring approval for cancellations
- requiring approval for discounts
- recording unsold cooked food
- tracking bar stock separately
- recording cash settlements
- tracking staff actions
- producing daily reports
## 5. Sales Growth Controls
The system shall increase sales through:
- AI-enabled website lead capture
- customer CRM
- promotions
- product performance tracking
- waiter performance tracking
- service motivation dashboard
- delivery tracking
- repeat-customer monitoring
## 6. Mobile-First Rule
The system must work properly on:
- smartphones
- tablets
- laptops
- desktops
Waiters must be able to use smartphones as POS devices.

# Developer Rules
This document is binding.
## 1. No Guessing
Developers must not guess:
- where a file belongs
- which system owns data
- which API endpoint to call
- which department owns a workflow
- which product category to use
- which approval rule applies
If unclear, the developer must stop and request clarification.
## 2. Brand Rule
Always refer to the system as:
**Meat Lovers CIMS powered by YohPal**
## 3. Mobile-First Rule
Every frontend screen must be usable on a smartphone.
## 4. API Rule
Frontend apps must not talk directly to the database.
All data must pass through the PHP backend API.
## 5. Department Rule
Every operational action must belong to a department:
- SUPPLIERS
- STORE
- KITCHEN

- SERVICE
- DISPATCH
- BAR
- UNSOLD_FOOD
- HRM
- CRM
- DELIVERIES
- ASSETS
- FINANCE
## 6. Audit Rule
Every sensitive action must be auditable.
Sensitive actions include:
- stock adjustment
- order cancellation
- discount
- refund
- cash settlement
- bar stock movement
- unsold food declaration
- supplier invoice entry
- asset write-off
